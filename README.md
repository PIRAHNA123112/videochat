# WebRTC Video Chat Application

Полноценное приложение для видеозвонков с использованием WebRTC и собственного signalling сервера.

## Структура проекта

### Android приложение
- **MainActivity.kt** - Главный экран с вводом названия комнаты
- **VideoCallActivity.kt** - Экран видеозвонка с WebRTC
- **activity_main.xml** - Разметка главного экрана
- **activity_video_call.xml** - Разметка экрана видеозвонка

### Signalling сервер
- **server/server.js** - WebSocket сервер для обмена SDP и ICE candidates
- **server/package.json** - Зависимости Node.js

## Как запустить

### 1. Запуск signalling сервера

```bash
cd server
npm install
npm start
```

Сервер запустится на порту 3000.

### 2. Настройка Android приложения

1. Откройте проект в Android Studio
2. Синхронизируйте Gradle файлы
3. В `VideoCallActivity.kt` измените `SERVER_URL` если необходимо:
   - Для эмулятора Android: `ws://10.0.2.2:3000`
   - Для реального устройства: `ws://ВАШ_IP_АДРЕС:3000`

### 3. Запуск приложения

1. Подключите Android устройство или запустите эмулятор
2. Запустите приложение из Android Studio
3. Введите название комнаты
4. Нажмите "Подключиться к комнате"

## Функционал

### Видеозвонок
- Отображение локального и удалённого видео
- Переключение микрофона (вкл/выкл)
- Переключение камеры (вкл/выкл)
- Завершение звонка

### Чат
- Отправка текстовых сообщений (базовая реализация)

## Технологии

### Android
- **WebRTC (google-webrtc)** - Библиотека для WebRTC
- **OkHttp** - HTTP клиент для WebSocket соединения
- **SurfaceViewRenderer** - Отображение видео потоков

### Сервер
- **Node.js** - JavaScript runtime
- **WebSocket (ws)** - Сервер WebSocket
- **Express** - Web фреймворк

## Как работает

1. Пользователь вводит название комнаты
2. Приложение подключается к signalling серверу через WebSocket
3. При подключении второго участника к той же комнате:
   - Первый создаёт SDP offer
   - Второй создаёт SDP answer
   - Обмениваются ICE candidates
4. Устанавливается P2P соединение через WebRTC
5. Начинается передача аудио и видео

## Примечания

- Для работы в реальной сети нужен TURN сервер (в текущей реализации используется только STUN)
- Приложение требует разрешения на камеру и микрофон
- Для тестирования на реальных устройствах signalling сервер должен быть доступен по сети
